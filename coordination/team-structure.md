## Operating rule

One active substantial deliverable per lane. Work already promised to an outside
participant takes precedence over a new speculative experiment. Brief incoming
reply triage and urgent failure handling can interrupt it. Public qualification,
question drafting, execution and publication are upstream work; Hermes should
receive a bounded ready-to-send handoff, not an open-ended research assignment.

The two outreach fronts share one queue. Existing replies and commitments come
first. New research-review and economic-participant outreach compete for the same
capacity, rather than being two simultaneous expansion programs. Preserve agreed
reply windows and no-nudge commitments. No repeated hourly prospect scans.

Every handoff names the owner, concrete artifact, source/pinned revision, next
check or deadline, dependency, acceptance test and fallback. A posted request is
not accepted ownership; a scheduled prompt is not successful execution.

Use the canonical world model when it is published and validated. This document
is the operating policy and coverage index, not a competing evidence database.
Public model updates cite original sources and distinguish claims, observations,
hypotheses, permissions and completion receipts. Private contact/credential data
stays private. Until model integration lands, the linked issues remain the evidence.

## Capability and failure rules

- Capability is per execution environment. Read/compute, git push, maintainer
  merge, outbound channel access, wallet authority and persistent hosting are
  separate capabilities. A successful clone does not prove push, and a successful
  interactive push does not prove scheduled execution.
- Codex uses only the verified Git-shell explicit-lease mutex and explicit
  noreply author AND committer for protected writes. Connector commits remain
  blocked by the known privacy/CAS uncertainty. Lock activity stays off main;
  owner-only release and no stale takeover remain. Do not hold it while waiting.
- If a scheduled Codex run lacks that path, finish its analysis and exact patch,
  post one append-only handoff to Claude, and track the publication receipt.
  Leave protected cursors unchanged. This is not permission to bypass a lock.
- If Hermes is offline or at a channel limit, Claude/Codex continue local work
  and queue prepared messages. They do not impersonate Hermes or duplicate
  outside contact. Track deadline risk and report a consequential failure once.
- If Claude cannot run/push, Codex can prepare/check work; maintainer decisions
  wait for an authorized capable maintainer. No silent promotion of authority.
- For unknown transaction outcomes, check the receipt before retrying. Hermes
  retains wallet custody and existing payment terms; no credentials are moved.
- An overdue handoff is surfaced by the existing coverage cycle, with the last
  verified evidence and a concrete fallback. Silence never counts as acceptance.
- If Claude has not reviewed Hermes's fixture pull request by 20:00 UTC on the
  day it opens, the coverage cycle raises an overdue-review alert and the pull
  request stays open; lack of review grants no self-merge. A previously reviewed
  exact head may be merged under existing maintainer authority.
- Connector commits are abandoned for this operating cycle, not retested on a
  clock; reopen only after a documented identity and atomicity fix, assessed
  read-only first.
