# Keeping the blog and the Omnequa journal in step

Claude Code (AI), November 1, 2026. Operator direction of November 1: the blog
must be kept in sync with the Omnequa journal; make the change and update the
process. This is the operating record of that process. It changes no schedule,
category rule, cap, contact route or authority, and it is not a second queue.

## Decision served, evidence, simpler route, stop condition

- **Decision served.** A reader of omnequa.org/journal and a reader of
  [Credit Among Strangers](https://github.com/scottonchain/microcredit-vision)
  see the same dated record, and the team can answer "is this post live on
  omnequa.org?" from the repository alone. Publication is a means; it is not
  demand, a qualifying case or human benefit, and it adds no exposure under the
  [north star](NORTH_STAR.md) scorecards (reserve survival and human benefit per
  sponsor dollar). The lending qualification's **NONE QUALIFIES** stands.
- **Evidence sought.** Two checks pass on every integrated commit: the blog's
  `python3 tools/build.py --check` and this testbed's journal check (below).
  A public read of `https://omnequa.org/journal/` after a publication shows the
  new post with the "latest edition, shared with our GitHub journal" status line.
- **Competing simpler route.** Have the site read only the canonical feed and
  keep no bundled copies. Rejected for now: the bundled edition is what the site
  renders first and what it shows when the GitHub read fails, and the Sites host
  deploys a static `dist/`. The copies stay, but they are generated and checked,
  never hand-copied.
- **Stop or change.** If the Sites host can serve the canonical feed directly, or
  a month of receipts shows the bundled edition is never used, drop the copies
  and simplify the build. If the two checks disagree, the testbed check is the
  one in error until shown otherwise, because the blog build is the renderer.

## Finding at vision main `b49d21b` (November 1)

The canonical export `omnequa/feed.json` was already generated by the blog
build and covered by `--check`. The four files the site bundles were hand-copied
and nothing checked them: `omnequa/content/blog-feed.json`,
`omnequa/content/blog-atom.xml`, `omnequa/dist/journal-feed.json` and
`omnequa/dist/feed.xml`. They matched on November 1 (91 posts), so nothing was
out of step yet; the next post would have left the saved edition behind until
someone remembered to copy.

## Process

1. **Write or change a post** in `posts/` under the vision rules (one subject,
   250 to 500 words, VERIFY rows, political exclusion, spacing, caps). An
   archive import goes through `omnequa/integration/prepare_news_import.py`
   once, keeping its source ID and date; it is never a second copy.
2. **Build, then check, in the same commit.** `python3 tools/make_images.py`
   when a new illustration is needed, `python3 tools/build.py`, then
   `python3 -m unittest discover -s tools -p 'test_*.py'` and
   `python3 tools/build.py --check`. The diff now includes the five journal
   files; inspect it and commit them with the post. A commit that touches
   `posts/` without them fails `--check`.
3. **Integrate to `main`** through the existing noreply-safe route and lease
   ([GITHUB_WRITE_ROUTE.md](GITHUB_WRITE_ROUTE.md); never the merge button).
   The post is on omnequa.org/journal as soon as `main` carries it, because the
   site reads `omnequa/feed.json` from `main`. GitHub raw caching can delay this
   by minutes; it needs no deploy, job or credential.
4. **Companions and receipts are unchanged.** A new post still needs its agent
   board mirror and Moltbook companion in `editorial/agent-distribution.json`;
   the eight archive imports do not.
5. **Redeploy the site when the site changes**, not for a post. The Codex lane
   runs the site build (`python3 omnequa/tools/build.py`, then
   `python3 omnequa/tools/check.py`, which now also compares the copies with
   the canonical export) and the native Sites save/deploy, and records a
   receipt: source commit, deployment time, one public URL read. The 07:00
   America/Denver maintenance window in the charter is the natural slot; a
   redeploy refreshes the saved edition the site shows while the GitHub read
   is pending or failing.
6. **Cross-checkout check**, with the five checkouts side by side:
   `python microcredit-agent-testbed/coordination/check_workspace.py --root .`
   now includes the journal; alone, `python coordination/omnequa_journal_sync.py
   --vision ../microcredit-vision`. Run it at the weekly engagement read and
   before any claim that the journal is current.

## When a check fails

| Observation | Action |
| --- | --- |
| `--check` says "journal out of step with posts/" | Run `python3 tools/build.py`, inspect the diff, commit the journal files with the post. Do not hand-edit a copy. |
| Site check says a copy differs from `feed.json` | Rebuild the blog first (it writes the copies), then the site, then rerun the site check. |
| Testbed check reports a difference the blog `--check` does not | Compare the two readers; the blog build is the renderer. Fix the testbed check or the checkout, record the reason here. |
| omnequa.org shows "Showing the saved edition" | The browser read of `omnequa/feed.json` from `main` failed. Check the raw URL and GitHub status; the saved edition is the last deployed `dist/journal-feed.json`, so a redeploy refreshes it. Not a publication failure. |
| A post is on `main` but not on omnequa.org/journal after an hour | Confirm `omnequa/feed.json` on `main` carries the slug; then it is a cache or client read problem, recorded on board 15 for the Codex lane. |
